## Isolated implementation

- `native/build_desktop.sh` builds an ad hoc signed menu-bar app with the installed Command Line Tools. The bundle belongs to `local.fwnivaen.jarvis.desktop` and stays under this worktree's ignored `.local/` directory. No login item or LaunchAgent was registered.
- The menu has a read-only voice-permission check. `--check-permissions` reports the same statuses without prompting or opening the microphone. `--measure-mic` takes two short in-memory audio samples and reports first-buffer latency and meter activity. `--check-hotkeys` reports registration and any delivered key events without opening the microphone. `--install-speech-model` checks or requests Apple's local English model. `tools/check_speech_model.sh` verifies transcription using generated speech and the signed app's model reservation. Demo mode accepts `JARVIS_ISLAND_DEMO_STATE` to hold one named state and `JARVIS_ISLAND_DEMO_HOLD` to exit after a chosen number of seconds when the executable is launched directly.
- Hold Control–Shift–Space for speech, use Option–Escape to cancel, and Option–Command–M to mute. Push-to-talk and mute request exclusive global registration; startup diagnostics record the status of all three shortcuts. Mute changes show an Island notice and update the menu title immediately. The menu also offers Start listening / Finish listening to exercise the same capture path when the keyboard shortcut is unavailable. Plain Escape is registered only during an active voice operation. `--ask` and `say` are available. Normal mode briefly shows a readiness notice in the Island.
- One microphone tap drives on-device transcription and the Island meter. The new app uses installed `SpeechTranscriber` assets when present and falls back to `SFSpeechRecognizer` with on-device recognition required. The current build reports the enhanced English model as installed. It requests legacy speech authorization only when it needs the legacy fallback. The menu offers an explicit model download action. Spoken replies use `AVSpeechSynthesizer` with a British voice preference. Muted replies advance text at 180 words per minute.
- The SwiftUI Island implements the active, approval, transient, notification, ready and hidden priority model; answer/failure/status classification; UTF-16 word synchronization; notch and flat pill layouts; a runtime Metal orb; a Canvas fallback; reduced-motion response; and a non-activating panel across Spaces. It can be disabled in the menu. Snapshot mode does not register hotkeys, open the microphone or call the server.
- The desktop watcher polls canonical `/stage2/tasks`, with a fallback to the existing `/workflows` endpoint after a 404, at three seconds while busy and thirty seconds while idle. It shows verified background work, ignores history on its first poll and deduplicates terminal transitions. Failed polls preserve known state and older overlapping responses cannot replace newer ones. Visual completion notices are on by default. “Speak background updates” is opt-in; summaries wait behind an active conversation and respect mute, pause, supported availability signals and quiet hours. Canonical `action_approvals` combines pending note/preference decisions, with legacy `note_actions` fallback. Review opens the real Work queue at `/#approvals`. General consequential Work/external-action approvals remain unsupported. Explicit background-status questions use owned-task and cleanup counts without a model call.
- `voice_bridge.py` and the new Swift helper share a per-user advisory microphone lock. This prevents two *updated* helpers from recording together after deployment. The currently running server has not loaded this change.
- Work admission now defaults to two tasks through `TASK_MAX_CONCURRENT`, with strict 1–8 validation and a fail-closed one-task fallback for invalid configuration. Each task has independent cancellation, checkpoint, bridge-process and cleanup ownership. Shared model/tool concurrency remains bounded at three; chat keeps one request owner. A cancelled task retains its admission until callbacks and bridge cleanup settle. The optional execution scheduler retains its existing one-owner default.
- `task_api.py` exposes canonical catalog/detail projections from existing Work records. Its dry-run preview uses actual recipe roles/criteria, permitted read tools and configured time/worker/tool/model budgets, while disclosing that execution persists questions, results, source passages and tool journals privately. Preview does not initialize storage, admit a task, read source contents or call a model/tool. `/stage2/tasks`, `/stage2/tasks/task?id=…` and same-origin POST `/stage2/tasks/plan` are wired and boundary-tested. The Work preview was exercised through an isolated real HTTP server and visible browser UI: the actual recipe appeared and no task started. Native canonical/fallback polling passed a controlled HTTP fixture; live task transitions after activation remain unaccepted. General Work approval and undo capabilities remain explicitly unsupported; separate note/preference controls are described below.
- The current native extension adds fixed phase/status VoiceOver announcements that avoid speaking transcript or answer content unsolicited, a real `IslandText` render evidence path, and tested orb fallback/frame-rate behavior. Source now includes listening expansion after the first words, truncated-text fade, streaming caret, word-arrival fade/rise, peek sizing, padded panel bounds, press scaling, row transition timing, delayed collapse and `JARVIS_ISLAND_SLOWMO`. The final native checker passed. A single geometry driver produced actual intermediate expansion and collapse frames. Independent Core Animation microphone bars use the existing normalized meter, and thinking/working shimmer runs in the render server. Reduce Motion removes these animations while retaining useful indicators. Synthetic real-layer frames are checked separately from snapshots.
- `note_actions.py` adds a durable, bounded queue for edits to existing notes only, backed by the existing private control store and native write journal. Five-minute approval is bound to the exact note identity, text and revision. One-hour undo requires the exact saved revision; stale, repeated, expired and interrupted outcomes fail closed. The note editor and Mission Control expose real review/save/reject/undo controls. No external action or new model tool is enabled. [Controls and storage](LOCAL-CONTROLS.md).
- `health_readiness.py` and `/health` provide on-demand metadata checks and first-run guidance in Settings/Voice. The readiness check itself opens no microphone, calls no model, reads no notes and opens no database. Its HTTP wrapper reads existing backend/settings through normal loaders and returns no credentials or private paths. Optional scheduled operations are a separate, explicit setting described below.
- Background notices use a bounded in-memory queue with deduplication and thirty-second expiry. Public inactive-session, display-sleep and system-sleep notifications plus explicit Pause background updates defer delivery; expired notices are dropped. New York quiet hours also defer background notices. These are narrow signals, not call, DND, screen-sharing or guaranteed immediate lock detection. Speech delegates fence old utterances so cancellation callbacks cannot finish a later reply.
- `document_export.py` creates a bounded editable DOCX in memory, with escaped Unicode paragraphs, a heading and no external relationships. The same-origin `/export/word` route returns a download without writing a server-side document; completed Work answers offer that download. It is distinct from the existing document-import module. XML/package, input limits, HTTP origin/download and macOS text round-trip checks passed; actual Word opening and visual layout remain manual acceptance.

## Prepared local memory and operations expansion

- **Obsidian brain:** `obsidian_brain.py` and `vault_files.py` share ordinary Markdown, aliases, tags and wikilinks with a separate Jarvis Brain folder. Settings can prepare the proposed new folder, refresh notes, change the passage budget and disconnect after restart. Folder connection/disconnection applies at server startup so active tasks keep their source scope. Existing demonstration notes are preserved. No Obsidian community plugin or sync service is required; the staged app is not installed or opened yet.
- **Local retrieval and limits:** incremental SQLite FTS5 indexes changed notes and removes deleted/excluded notes on a successful refresh. Limits are 1,000 Markdown files, 800,000 bytes per note and 64 MiB total text. Hidden paths, `Private`, `Secrets`, symlinks and `jarvis_private: true` / `jarvis_exclude: true` notes are excluded. Front matter is a bounded supported subset, not a full YAML engine. Search checks current note revisions before returning excerpts; source links open the original note in Obsidian.
- **Bounded model context:** at most six passages of up to 1,800 characters share a 6,000-character default aggregate source budget (configurable 1,000–12,000); recent verbatim history is capped at 3,000 characters. Explicit local note searches and exact note title/path/alias reads can answer without a model, while reasoning remains on the signed-in included Codex route. Session counters report source characters and direct lookups, not billed tokens or subscription savings. Notes are untrusted material and are not an automatic transcript archive. Removing a note does not erase old exports or retained checkpoints.
- **Preference review:** `preference_actions.py` reuses the durable note approval state machine with a separate queue for explicit Settings set/forget choices. Decisions bind the complete before/after preference state, expire after five minutes and refuse stale or uncertain outcomes. One-hour undo requires the entire current state to match the approved result. Work and Island show both note and preference decisions; this is not a universal action/undo mechanism or a password store.
- **Activity and selected export:** `/activity` projects bounded retained task and note/preference decision metadata without note contents or chat transcripts; saved-work links use existing Work controls. Settings offers selected Markdown notes, preferences, allowlisted settings, task questions/results and activity as an in-memory ZIP. Private/hidden/symlinked notes, configuration files, credentials, checkpoints and tool journals are excluded. Recognized credential forms in selected text are redacted, but user-authored text still needs review before sharing. Export is not a complete backup or restore system.
- **Local operations:** opt-in daily metadata checks run only while the server runs, at a New York local time, without model calls or an OS startup scheduler. Optional bounded battery/network snapshots can defer these checks under configured resource policy. Network configuration is not proof of internet connectivity; unknown signals stay unknown. Quiet hours and speech settings are explicit controls, not inferred presence.
- **Native/web speech contract:** canonical task catalogs carry strict versioned `delivery_policy` with quiet state, speech choice, revision and `managed`. An unmanaged policy preserves the existing local speech choice; malformed/absent policy preserves the last accepted state. An explicit native toggle sends only the speech field plus expected revision to `/operations/settings`, disables its control while pending and adopts the choice after acknowledgement. Conflicts refresh the current choice; failures preserve the prior choice. Generation fences prevent stale polls undoing a save. Older servers with no Operations endpoint retain local fallback. This synchronizes background speech, not every native preference; updates arrive through polling.
- **Hands-free preview:** “Try hands-free (preview)…” is off every launch and asks before continuous local microphone transcription. The installed on-device English model is required. “Hey Jarvis” activates a bounded command: 1.1-second silence detection, 20-second maximum command and six-second follow-up after a hands-free reply. Ambient text is bounded and never submitted before a wake phrase. PTT yields/waits for shared capture ownership; cancellation, mute, user switching and display/system sleep disable the preview. Analyzer cleanup retains the per-user voice lock until it settles. Consent explicitly says disable before locking because immediate screen-lock detection is unverified. No live preview capture has been accepted; double-clap is not implemented.

The implementation is a useful local voice/Island slice of the attached vision. It does not establish that all of the requested assistant capabilities are complete. The [feature catalog and roadmap](voice-island-catalog.md) records every main capability class and its next gate.
