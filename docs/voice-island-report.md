## Isolated implementation

- `native/build_desktop.sh` builds an ad hoc signed menu-bar app with the installed Command Line Tools. The bundle belongs to `local.fwnivaen.jarvis.desktop` and stays under this worktree's ignored `.local/` directory. No login item or LaunchAgent was registered.
- The menu has a read-only voice-permission check. `--check-permissions` reports the same statuses without prompting or opening the microphone. `--measure-mic` takes two short in-memory audio samples and reports first-buffer latency and meter activity. `--check-hotkeys` reports registration and any delivered key events without opening the microphone. `--install-speech-model` checks or requests Apple's local English model. `tools/check_speech_model.sh` verifies transcription using generated speech and the signed app's model reservation. Demo mode accepts `JARVIS_ISLAND_DEMO_STATE` to hold one named state and `JARVIS_ISLAND_DEMO_HOLD` to exit after a chosen number of seconds when the executable is launched directly.
- Hold Control–Shift–Space for speech, use Option–Escape to cancel, and Option–Command–M to mute. Push-to-talk and mute request exclusive global registration; startup diagnostics record the status of all three shortcuts. Mute changes show an Island notice and update the menu title immediately. The menu also offers Start listening / Finish listening to exercise the same capture path when the keyboard shortcut is unavailable. Plain Escape is registered only during an active voice operation. `--ask` and `say` are available. Normal mode briefly shows a readiness notice in the Island.
- One microphone tap drives on-device transcription and the Island meter. The new app uses installed `SpeechTranscriber` assets when present and falls back to `SFSpeechRecognizer` with on-device recognition required. The current build reports the enhanced English model as installed. It requests legacy speech authorization only when it needs the legacy fallback. The menu offers an explicit model download action. Spoken replies use `AVSpeechSynthesizer` with a British voice preference. Muted replies advance text at 180 words per minute.
- The SwiftUI Island implements the active, approval, transient, notification, ready and hidden priority model; answer/failure/status classification; UTF-16 word synchronization; notch and flat pill layouts; a runtime Metal orb; a Canvas fallback; reduced-motion response; and a non-activating panel across Spaces. It can be disabled in the menu. Snapshot mode does not register hotkeys, open the microphone or call the server.
- The desktop watcher polls canonical `/stage2/tasks`, with a fallback to the existing `/workflows` endpoint after a 404, at three seconds while busy and thirty seconds while idle. It shows a background “Working” state from verified workflow activity, ignores history on its first poll and deduplicates terminal transitions. A failed poll preserves the last known busy state. Visual completion notices are on by default. “Speak background updates” is opt-in in the menu; when enabled, summaries wait behind an active conversation and respect mute. The candidate now projects pending note edits from the durable local approval store into the Island. Review opens the actual Mission Control queue; resolving or expiring the edit clears the indicator. General Work action approvals remain unsupported because those workflows expose read-only tools. Explicit questions such as “What are you working on?” now report canonical owned-task and cleanup counts without a model call.
- `voice_bridge.py` and the new Swift helper share a per-user advisory microphone lock. This prevents two *updated* helpers from recording together after deployment. The currently running server has not loaded this change.
- Work admission now defaults to two tasks through `TASK_MAX_CONCURRENT`, with strict 1–8 validation and a fail-closed one-task fallback for invalid configuration. Each task has independent cancellation, checkpoint, bridge-process and cleanup ownership. Shared model/tool concurrency remains bounded at three; chat keeps one request owner. A cancelled task retains its admission until callbacks and bridge cleanup settle. The optional execution scheduler retains its existing one-owner default.
- `task_api.py` exposes canonical catalog/detail projections from existing Work records. Its dry-run preview uses actual recipe roles/criteria, permitted read tools and configured time/worker/tool/model budgets, while disclosing that execution persists questions, results, source passages and tool journals privately. Preview does not initialize storage, admit a task, read source contents or call a model/tool. `/stage2/tasks`, `/stage2/tasks/task?id=…` and same-origin POST `/stage2/tasks/plan` are wired and boundary-tested. The Work preview was exercised through an isolated real HTTP server and visible browser UI: the actual recipe appeared and no task started. Native canonical/fallback polling passed a controlled HTTP fixture; live task transitions after activation remain unaccepted. General Work approval and undo capabilities remain explicitly unsupported; separate note-edit controls are described below.
- The current native extension adds fixed phase/status VoiceOver announcements that avoid speaking transcript or answer content unsolicited, a real `IslandText` render evidence path, and tested orb fallback/frame-rate behavior. Source now includes listening expansion after the first words, truncated-text fade, streaming caret, word-arrival fade/rise, peek sizing, padded panel bounds, press scaling, row transition timing, delayed collapse and `JARVIS_ISLAND_SLOWMO`. The final native checker passed. A single geometry driver produced actual intermediate expansion and collapse frames. Independent Core Animation microphone bars use the existing normalized meter, and thinking/working shimmer runs in the render server. Reduce Motion removes these animations while retaining useful indicators. Synthetic real-layer frames are checked separately from snapshots.
- `note_actions.py` adds a durable, bounded queue for edits to existing notes only, backed by the existing private control store and native write journal. Five-minute approval is bound to the exact note identity, text and revision. One-hour undo requires the exact saved revision; stale, repeated, expired and interrupted outcomes fail closed. The note editor and Mission Control expose real review/save/reject/undo controls. No external action or new model tool is enabled. [Controls and storage](LOCAL-CONTROLS.md).
- `health_readiness.py` and `/health` provide on-demand metadata checks and first-run guidance in Settings/Voice. No microphone, model call, note read, database open, download or scheduled monitor occurs. The HTTP wrapper reads the existing private backend/settings through normal server loaders, returns no credentials or private paths, and declares those reads. Native settings remain in the menu; this is not a complete unified setup/export system.
- Background notices now use a bounded in-memory queue with deduplication and thirty-second expiry. Native session-inactive and display-sleep notifications defer delivery, and an explicit Pause background updates menu item pauses future delivery. These are narrow supported signals, not call, DND or screen-sharing detection. Speech delegates fence old utterances so cancellation callbacks cannot finish a later reply.
- `document_export.py` creates a bounded editable DOCX in memory, with escaped Unicode paragraphs, a heading and no external relationships. The same-origin `/export/word` route returns a download without writing a server-side document; completed Work answers offer that download. It is distinct from the existing document-import module. XML/package, input limits, HTTP origin/download and macOS text round-trip checks passed; actual Word opening and visual layout remain manual acceptance.

The implementation is a useful local voice/Island slice of the attached vision. It does not establish that all of the requested assistant capabilities are complete. The [feature catalog and roadmap](voice-island-catalog.md) records every main capability class and its next gate.
